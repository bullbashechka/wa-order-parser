# PRD: выгрузка корзин из WhatsApp Business в CSV

## Цель продукта

Нужно разработать приложение, которое автоматически принимает корзины, отправленные клиентами в WhatsApp Business, извлекает из них товары и сохраняет данные в CSV-файл. CSV-файл должен быть пригоден для открытия в Excel и Google Sheets без ручной обработки.

Приложение должно работать в фоне, сохранять авторизованную сессию WhatsApp, не требовать повторного сканирования QR-кода после перезапуска и защищать CSV от повторной записи одной и той же корзины.

## Технологии

Приложение разрабатывается на Node.js 18 или выше.

Для подключения к WhatsApp используется библиотека `whatsapp-web.js`.

Для отображения QR-кода в терминале используется `qrcode-terminal`.

Для записи CSV используется `csv-writer` или эквивалентная CSV-реализация, которая корректно создает файл, пишет заголовки и добавляет строки без потери существующих данных.

Для фонового запуска используется `pm2`.

Текущий репозиторий должен быть оформлен как приложение `wa-order-parser`: `package.json`, `README.md` и `index.js` должны относиться к этому приложению, а не к исходной структуре библиотеки `whatsapp-web.js`.

## Фича: авторизация в WhatsApp Business

Приложение должно подключаться к WhatsApp через WhatsApp Web.

При первом запуске приложение должно показать QR-код в терминале. Пользователь сканирует QR-код в WhatsApp на телефоне через раздел связанных устройств.

После успешной авторизации приложение должно сохранить локальную сессию с помощью `LocalAuth` в папку `.wwebjs_auth`.

При последующих запусках приложение должно использовать сохраненную сессию и не требовать повторного QR-кода, если сессия остается валидной.

В консоль должны выводиться только важные статусы авторизации: появление QR-кода, успешная готовность клиента и ошибки подключения.

## Фича: прием корзин из WhatsApp

Приложение должно слушать входящие сообщения WhatsApp и обрабатывать только сообщения типа корзины или заказа, которые WhatsApp передает как `order`.

Приложение должно обрабатывать только входящие заказы из личных чатов. Сообщения, отправленные самим подключенным аккаунтом, и заказы из групповых чатов не должны записываться в CSV.

Приложение должно обрабатывать только новые события, полученные во время работы приложения. При запуске не требуется читать историю чатов или искать корзины, которые пришли, пока приложение было выключено.

Обычные текстовые сообщения, медиа, звонки, реакции и другие типы событий не должны записываться в CSV.

При получении корзины приложение должно извлечь список товаров из заказа. Каждый товар из корзины сохраняется отдельной строкой в CSV.

Если одна корзина содержит несколько товаров, в CSV должно появиться несколько строк с одинаковыми датой, телефоном и ID сообщения, но с разными товарами.

Приложение не должно отправлять клиенту автоответы. Его задача только принять корзину и сохранить ее в CSV.

## Фича: CSV-файл заказов

Все заказы сохраняются в один файл `orders.csv`.

Файл должен находиться по пути, заданному в конфигурации. По умолчанию используется `orders.csv` в корне проекта.

Если CSV-файла еще нет, приложение должно автоматически создать его и записать строку заголовков.

CSV должен использовать разделитель `;`, чтобы файл удобно открывался в Excel в русской и европейской локали.

CSV должен записываться в кодировке UTF-8 с BOM, чтобы Excel корректно открывал русские заголовки и значения без ручного выбора кодировки.

CSV-значения должны корректно экранироваться по правилам CSV, если внутри значения есть разделитель, кавычки или перенос строки.

Каждая строка CSV соответствует одному товару из корзины.

Структура CSV:

```csv
Дата и время;Телефон;ID сообщения;Название товара;Количество;Цена;Валюта;Сумма позиции
```

Колонка `Дата и время` содержит дату и время обработки корзины в формате `YYYY-MM-DD HH:mm:ss`.

Дата и время должны записываться в часовом поясе `Asia/Almaty`.

Если WhatsApp передает отдельное время создания заказа, оно не используется для колонки `Дата и время`; в CSV фиксируется именно время успешной обработки корзины приложением.

Колонка `Телефон` содержит очищенный номер клиента без WhatsApp-суффикса, например `77001234567` вместо `77001234567@c.us`.

Колонка `ID сообщения` содержит уникальный ID входящего сообщения WhatsApp, по которому можно определить, была ли корзина уже обработана.

Колонка `Название товара` содержит название товара из WhatsApp. Перед записью нужно удалить лишние пробелы в начале и конце строки. Регистр символов менять не нужно.

Колонка `Количество` содержит количество товара, если WhatsApp передал это значение.

Колонка `Цена` содержит цену товара, если WhatsApp передал это значение.

Цена записывается в CSV в том виде, в котором ее передал WhatsApp. Приложение не должно делить цену на 100, округлять ее или выполнять другие преобразования формата.

Колонка `Валюта` содержит валюту товара, если WhatsApp передал это значение.

Колонка `Сумма позиции` содержит результат умножения количества на цену, если оба значения доступны.

Для расчета `Сумма позиции` приложение должно привести `Количество` и `Цена` к числам и умножить их. Если `Цена` не является числовым значением в формате, пригодном для `Number(...)`, сумма позиции должна оставаться пустой.

Если количество, цена или валюта отсутствуют в данных WhatsApp, соответствующие поля в CSV должны оставаться пустыми.

Если невозможно посчитать сумму позиции из-за отсутствия количества или цены, поле `Сумма позиции` должно оставаться пустым.

## Фича: защита от дублей

Приложение должно не допускать повторной записи одной и той же корзины.

Уникальность корзины определяется по ID входящего сообщения WhatsApp.

После успешной обработки корзины ID сообщения должен сохраняться в отдельный файл `processed-messages.json`.

При запуске приложение должно загружать `processed-messages.json` и использовать его для проверки уже обработанных сообщений.

Если `processed-messages.json` отсутствует, приложение должно считать список обработанных сообщений пустым и создать файл при первой успешной обработке корзины.

Если `processed-messages.json` существует, но содержит поврежденный JSON или данные неподходящего формата, приложение должно вывести ошибку в консоль, переименовать поврежденный файл в резервную копию с расширением `.bak` и продолжить работу с пустым списком обработанных сообщений.

Если приложение получает корзину с ID сообщения, который уже есть в `processed-messages.json`, такая корзина не должна повторно записываться в CSV.

Если корзина содержит несколько товаров, ID сообщения должен считаться обработанным только после успешной записи всех строк этой корзины в CSV.

## Фича: обработка ошибок записи

Если при записи в CSV произошла ошибка, приложение должно повторить попытку записи несколько раз.

Приложение должно выполнить 3 попытки записи: первую сразу, вторую через 500 мс после ошибки и третью через 1000 мс после второй ошибки.

Если после повторных попыток запись не удалась, приложение должно вывести ошибку в консоль и продолжить работу.

При неуспешной записи ID сообщения не должен добавляться в `processed-messages.json`, чтобы корзину можно было обработать повторно при следующем получении или после перезапуска.

Ошибка записи одного заказа не должна останавливать прием следующих сообщений.

## Фича: конфигурация через `.env`

Основные настройки приложения должны задаваться через `.env`.

В конфигурации должны поддерживаться следующие параметры:

```env
CSV_PATH=orders.csv
CSV_DELIMITER=;
TIMEZONE=Asia/Almaty
PROCESSED_MESSAGES_PATH=processed-messages.json
```

Если `.env` отсутствует или отдельные параметры не заданы, приложение должно использовать значения по умолчанию.

В репозитории должен быть пример конфигурации `.env.example` с безопасными значениями по умолчанию.

## Фича: запуск приложения

Приложение должно запускаться командой:

```bash
npm start
```

Команда `npm start` должна запускать основной файл приложения.

Основной файл приложения должен находиться в корне проекта и называться `index.js`.

Для разработки допускается запуск:

```bash
node index.js
```

Для фонового запуска приложение должно поддерживать запуск через `pm2`:

```bash
pm2 start index.js --name wa-order-parser
pm2 save
pm2 startup
```

## Фича: логирование

Приложение должно выводить в консоль только важные события:

- QR-код или сообщение о необходимости авторизации.
- Успешное подключение и готовность WhatsApp-клиента.
- Успешную запись корзины в CSV.
- Пропуск уже обработанной корзины.
- Ошибки подключения, чтения конфигурации, чтения файла обработанных сообщений и записи CSV.

Приложение не должно логировать каждое входящее сообщение, если оно не является корзиной.

Отдельный файл логов не требуется.

## Фича: документация

В проекте должен быть `README.md` с инструкциями для пользователя.

Документация должна описывать:

- Требование Node.js 18 или выше.
- Установку зависимостей.
- Настройку `.env`.
- Первый запуск и сканирование QR-кода.
- Повторный запуск без QR-кода.
- Проверку файла `orders.csv`.
- Запуск через `pm2`.
- Предупреждение о том, что `whatsapp-web.js` является неофициальной библиотекой WhatsApp.

## Критерии приемки

Приложение считается готовым, если тестовая корзина, отправленная на WhatsApp Business, создает строки в `orders.csv`.

Если корзина содержит несколько товаров, каждый товар должен быть записан отдельной строкой.

CSV должен содержать заголовки и использовать разделитель `;`.

CSV должен быть записан в UTF-8 с BOM и открываться в Excel с читаемыми русскими заголовками без ручного выбора кодировки.

Дата и время должны записываться в формате `YYYY-MM-DD HH:mm:ss` в часовом поясе `Asia/Almaty`.

Дата и время в CSV должны отражать время обработки корзины приложением, а не время создания заказа в WhatsApp.

Телефон клиента должен сохраняться в очищенном числовом формате без `@c.us`.

Приложение должно игнорировать собственные сообщения подключенного аккаунта и заказы из групповых чатов.

Приложение не обязано восстанавливать корзины из истории чатов после периода, когда оно было выключено.

Повторная обработка одного и того же ID сообщения не должна создавать дубли в CSV.

После перезапуска приложение должно использовать сохраненную WhatsApp-сессию без повторного QR-кода.

После запуска через `pm2` приложение должно продолжать работать в фоне и принимать новые корзины.

Если CSV-файл отсутствует, приложение должно создать его автоматически.

Если возникает ошибка записи CSV, приложение должно вывести ошибку, не останавливать процесс и не помечать сообщение как обработанное.

Если файл `processed-messages.json` поврежден, приложение должно сохранить его резервную копию с расширением `.bak`, продолжить работу и не падать при запуске.

## Ограничения

`whatsapp-web.js` является неофициальной библиотекой. WhatsApp может ограничить или заблокировать номер при агрессивном использовании, массовых рассылках или подозрительной активности.

Приложение не предназначено для массовых рассылок, автоматического общения с клиентами или высоконагруженного продакшна.

Для большого объема заказов и критически важного продакшна нужно рассмотреть переход на официальный WhatsApp Business API.
